# V2.2 — Dynamic Bulk Product Import

## Goal
Allow a tenant to import products in bulk while respecting the product fields that tenant has configured. Do not assume every business uses the same industry fields or hard-code yarn-specific columns.

## Import flow
1. User downloads a CSV template (and XLSX template if supported) generated from the business's current product schema/field definitions.
2. Template includes standard fields plus each configured custom field, with clear labels, stable field keys, required markers, allowed values, and examples where useful.
3. User uploads CSV/XLSX; system detects headers and offers column mapping when headers differ.
4. Parse and validate without writing records. Show total rows, valid rows, invalid rows, warnings, and row-level errors with row number and field.
5. User confirms import. Show progress and final created/updated/skipped/failed counts, with downloadable error report.

## Modes and matching
- Create-only mode is the safe default.
- Update mode is opt-in, uses a documented stable identifier (SKU where present), and requires a preview of changes before commit.
- Never silently overwrite a product when matching is ambiguous.
- Enforce unique constraints, required fields, data types, configured dropdown options, and business ownership on the server.

## File safety
- Enforce extension, MIME/content parsing, size, row, and column limits.
- Protect against spreadsheet formula injection in generated error/export files.
- Reject malformed or unsupported workbooks with actionable errors.
- Never trust client-side validation alone.

## Acceptance criteria
- Template reflects the tenant's currently configured product fields, including custom fields and required/option constraints.
- Imports work for at least two businesses with different field configurations.
- Invalid rows are identified before committing.
- Re-importing in create-only mode does not create accidental duplicates.
- Update mode previews every change and requires explicit confirmation.
- Unit/API tests cover validation, duplicates, permissions, limits, malformed files, and partial failure handling.
