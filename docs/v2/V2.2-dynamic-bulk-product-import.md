# V2.2 — Dynamic Bulk Product Import

## Goal
Import products in bulk while respecting the product fields configured by each tenant. Do not hard-code yarn-specific columns or assume every business uses the same fields.

## Import flow
1. Generate a downloadable CSV template (and XLSX where supported) from the tenant's current standard and custom product fields.
2. Include stable field keys, labels, required markers, dropdown options, and examples where useful.
3. Upload file; detect headers and allow column mapping.
4. Validate before writing; show total, valid, invalid and warning counts, with row/field-specific errors.
5. Require explicit confirmation, then show created/updated/skipped/failed counts and downloadable error report.

## Modes and matching
- Create-only is the safe default.
- Update mode is opt-in, matches using a documented stable identifier such as SKU, and previews changes before commit.
- Never silently overwrite an ambiguous match.
- Server validates required fields, types, configured options, unique constraints, and tenant ownership.

## File safety
- Enforce extension/content, file size, row and column limits.
- Handle malformed files with actionable errors.
- Protect generated exports from spreadsheet formula injection.
- Client validation is never sufficient by itself.

## Acceptance tests
- Templates reflect different tenant field configurations.
- Invalid rows are identified before commit.
- Create-only avoids accidental duplicates.
- Update mode previews each change and requires confirmation.
- Tests cover validation, permissions, duplicates, limits, malformed files, and partial failures.
